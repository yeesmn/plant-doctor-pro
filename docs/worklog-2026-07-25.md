## 3. Phase 5.1 — moisture converted to percent (commit `948c30d`)

Decision: **convert on the device**, so `plant_data.moisture` only ever holds percent.

- `config.h` / `config.example.h` — `MOISTURE_RAW_DRY` / `MOISTURE_RAW_WET`.
- `sensor.ino` — `moistureToPercent()`: linear map, clamped 0–100, `-1` passes through,
  `#error` if DRY <= WET.
- `datafiltering.ino` — averages raw, converts once → `filtered_moisture_pct`.
- `plant_status.ino` — thresholds now `30` / `80` percent, plus a `-1` guard that did not
  exist before (a failed read used to fall through to "needs water").
- `wifi_post.ino` — POSTs the percent value.
- `dashboard-view.ts` — moisture rejoins `computeHealth()`; card renders `%` via
  `inRange()`.
- `migrations/2026-07-25_moisture_to_percent.sql` — converts rows already stored as raw.

`plant_types` needed no change; all eight seeded species were already in percent.

## 4. Phase 5.2 — timestamps now carry a time zone

`TIMESTAMP` (no zone) meant PostgREST returned `2026-07-25T01:00:00` with no offset, and
`new Date()` reads that as *local* time — every reading looked 9 hours old in KST, and the
`.gte("recorded_at", since)` window in `fetchReadings()` was skewed by the same amount.

- `schema.sql` — all five timestamp columns are `TIMESTAMPTZ`.
- `migrations/2026-07-25_timestamptz.sql` — converts the live columns, reinterpreting the
  stored values as UTC (with a step-0 check that the server really is on UTC).
- `dashboard-view.ts` — `buildHistory()` now groups by `localDayKey()`. Separate bug found
  on the way: it bucketed by the **UTC** day while `shortDate()` labelled in **local**
  time, so an evening KST reading landed in the previous day's bucket and two points could
  end up with the same label.

No client-side offset maths was added — once the column has a zone, `new Date()` is right
on its own.
