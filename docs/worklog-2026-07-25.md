## 3. Phase 5.1 — moisture converted to percent (`8508c48`)

Decision: **convert on the device**, so `plant_data.moisture` only ever holds percent.

- `config.h` / `config.example.h` — `MOISTURE_RAW_DRY` / `MOISTURE_RAW_WET`.
- `sensor.ino` — `moistureToPercent()`: linear map, clamped 0–100, `-1` passes through,
  `#error` if DRY <= WET.
- `datafiltering.ino` — averages raw, converts once → `filtered_moisture_pct`. Averaging
  first keeps the clamp from biasing the mean.
- `plant_status.ino` — thresholds now `30` / `80` percent, plus a `-1` guard that did not
  exist before (a failed read used to fall through to "needs water").
- `wifi_post.ino` — POSTs the percent value.
- `dashboard-view.ts` — moisture rejoins `computeHealth()`; card renders `%` via
  `inRange()`.
- `migrations/2026-07-25_moisture_to_percent.sql` — converts rows stored in raw units.

`plant_types` needed no change; all eight seeded species were already in percent.

**Open question the hardware will answer:** a reading of `318.4` raw maps to **94.3 %**
under the committed placeholders (620 / 300). Unless the pot really was saturated, that
says the placeholders do not match this probe — 318 sits almost on top of the assumed
"submerged" reference. Real measurements settle it.

## 4. Phase 5.2 — timestamps now carry a time zone (`c4416dc`, migration run)

`TIMESTAMP` (no zone) meant PostgREST returned `2026-07-25T01:00:00` with no offset, and
`new Date()` reads that as *local* time — every reading looked 9 hours old in KST, and the
`.gte("recorded_at", since)` window in `fetchReadings()` was skewed by the same amount.

- `schema.sql` — all five timestamp columns are `TIMESTAMPTZ`.
- `migrations/2026-07-25_timestamptz.sql` — converts the live columns, reinterpreting the
  stored values as UTC (with a step-0 check that the server really is on UTC).
- `dashboard-view.ts` — `buildHistory()` now groups by `localDayKey()`. Separate bug found
  on the way: it bucketed by the **UTC** day while `shortDate()` labelled in **local**
  time, so an evening KST reading landed in the previous day's bucket and two points could
  end up carrying the same label.

No client-side offset maths was added — once the column has a zone, `new Date()` is right
on its own.

**Ran in Supabase and verified:** `recorded_at` now comes back as
`2026-07-09 23:11:01.663528+00`.

## 5. Phase 5.3 — service-role key out of the frontend (`c4f13dd`)

reads `process.env.SUPABASE_*` only — but they can go on the next pass.

## 7. ⚠ 5.1 IS NOT VERIFIED ON HARDWARE

**The sketch has not been compiled or uploaded.** There is no `arduino-cli` on this
machine, so every firmware change above is unproven — only the frontend was built
(`vite build`, passes). Work through this before trusting the data:

- [ ] **It compiles.** Open `arduino/plant_doctor_pro/plant_doctor_pro.ino` in the Arduino
      IDE and Verify. Watch for anything involving `filtered_moisture_pct` or
      `moistureToPercent` — the new cross-file symbols (`globals.h` declares both).
- [ ] **`config.h` has the calibration macros.** It is gitignored, so if the copy that
      actually gets uploaded lives somewhere else (an Arduino IDE sketchbook folder), the
      new `MOISTURE_RAW_DRY` / `MOISTURE_RAW_WET` defines must be added there too —
      otherwise the build fails with "not declared in this scope".
- [ ] **Measure the two reference points.** Serial Monitor, `moisture(raw)=` line: probe
      dry in open air → `MOISTURE_RAW_DRY`; submerged to the marked line →
      `MOISTURE_RAW_WET`. Put both in `config.h` and re-upload.
      **The committed 620 / 300 are typical capacitive values, not measurements.**
- [ ] **Percent looks sane.** Serial prints `Moisture: xx % (raw yyy)`. Dry soil should
      read low, and watering the pot should push the number up within a cycle or two. If it
      moves the wrong way the probe is resistive, not capacitive — swap the two constants
      and invert the formula in `moistureToPercent()`.
- [ ] **`plant_status` reacts.** Below 30 % → `needs water`, above 80 % → `too wet`.
      Easiest check: lift the probe out of the soil and wait one POST cycle.
- [ ] **A `-1` moisture reading no longer says "needs water"** — the regression the new
      guard prevents.
- [ ] **The row in Supabase is 0–100**, not 0–1023.
- [ ] **The 2026-07-09 raw rows are dealt with** —
      [migrations/2026-07-25_moisture_to_percent.sql](../web/backend/database/migrations/2026-07-25_moisture_to_percent.sql),
      scoped to the real `device_id`. Deleting them is cleaner than converting: they predate
      the calibration, so any conversion is guesswork over data nobody needs.
- [ ] **Dashboard**: moisture card shows `%`, the health score moves with moisture (it was
      excluded before), "last updated" tracks minutes, and the history chart shows one
      point per local day with no repeated labels.
