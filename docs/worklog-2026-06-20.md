## 2. Arduino — restructure + complete the data pipeline

**Folder structure** — moved the five `.ino` files into `arduino/plant_doctor_pro/`
so the folder name matches the main sketch (required for the Arduino IDE to open it).

**New files**
- `globals.h` — `extern` declarations for cross-file globals + function prototypes.
  Arduino auto-prototypes *functions* across `.ino` files but **not** *variables*, so the
  modular split would not have compiled without this.
- `config.h` (gitignored) — real secrets: WiFi creds, server IP/port, `DEVICE_ID`.
- `config.example.h` (committed) — template to copy into `config.h`.

**Code changes**
- `plant_doctor_pro.ino` — now the "conductor": holds `setup()` + `loop()`.
- `wifi_post.ino` — WiFi/POST helpers only; secrets pulled from `config.h`.
  - **Fixed the integration bug:** the POST body was missing the required `device_id`
    (every request would have returned HTTP 400). Now sends `device_id` plus
    `humidity`, `roll`, `pitch` alongside `moisture`/`light`/`temperature`.
  - Removed the trailing slash on the POST path (`/api/sensor-data`).
- `sensor.ino` — minimal changes only (reading logic untouched): added the `globals.h`
  include and moved the moisture `pinMode` into `sensorsInit()`.
- `datafiltering.ino`, `plant_status.ino` — added the `globals.h` include.

**Action still required by you:** fill in real values in `arduino/plant_doctor_pro/config.h`,

## 3. Frontend — Phase 4 (live data, in progress)

Decisions: **read directly from Supabase** (RLS enforces per-user access) and
**auto-select the newest device**.

**New files**
- `src/app/api/fetch-data.ts` — typed row types + queries
  (`fetchNewestDevice` with `plant_types` join, `fetchReadings`).
- `src/app/api/dashboard-view.ts` — transforms raw rows into the shapes the components
  render (health score, sensor states, daily-averaged history).

**Wired to live data (with loading / empty / error states):**
- `Dashboard.tsx` — orchestrates one fetch and passes props down.
- `HeroSection` — name, species, health score, status, last-updated, days monitored.
- `SensorRow` — latest moisture/light/temp/tilt + sparklines + in-range states.
- `HistoryChart` — daily-averaged moisture & temperature, sliced by 7D/30D/90D.

**Still on mock (intentionally):**
- `CareSuggestions` — radar is derivable later; suggestion text needs the
  `care_suggestions` table wired in.
- `DeviceFooter` — board / firmware / uptime / signal are **not in the schema**.

**Known data-model gaps (handled honestly, not faked):**
- **Moisture units:** firmware sends *raw* analog (0–1023), but `plant_types` ranges and
  the UI assume **%**. Moisture is shown as raw and excluded from the health score until
  the sensor is calibrated.
- **`-1` sentinel:** failed reads are treated as "no data" (`—`), not real values.
- **No watering log** → watering markers removed from the history chart.

## 4. Local test / mock mode

Added a way to verify the dashboard with **no Supabase login and no SQL**:
- `src/app/api/mock-readings.ts` — generates 90 days of synthetic readings (4/day),
  including a too-hot latest temperature and an occasional failed (`-1`) read.
- Toggle: set `VITE_USE_MOCK=true` in `web/frontend/.env` (currently enabled).
  Bypasses the auth gate (`App.tsx`) and feeds mock data through the real
  `buildDashboardView()` pipeline.

**To run:** `cd web/frontend && npm run dev` → opens straight to the dashboard.
**To use real data again:** remove/disable `VITE_USE_MOCK` in `.env` and restart `npm run dev`.
