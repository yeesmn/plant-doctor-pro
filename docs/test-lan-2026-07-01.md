# LAN Test Plan — Send Real Sensor Data (2026-07-01)

Goal: verify the **Arduino → backend → Supabase** path over the local network.
No public server: the PC runs the Express backend, the Arduino POSTs to the PC's
LAN IP over WiFi.

Pipeline: `plant_doctor_pro.ino` → POST `/api/sensor-data` → Express (port 3000) →
Supabase `plant_data` table.

---

## Pre-flight checklist (do this first)

- [ ] **`config.h` exists with real values** (`arduino/plant_doctor_pro/config.h`,
      gitignored — copy from `config.example.h`):
  - `SERVER_IP` = the PC's **LAN IPv4** (run `ipconfig`, e.g. `192.168.0.25`) — NOT `localhost`
  - `SERVER_PORT` = `3000`
  - `WIFI_SSID` / `WIFI_PASS` = real WiFi creds
  - `DEVICE_ID` = a UUID that **exists** in the Supabase `devices` table
- [ ] **Backend `.env` exists** (`web/backend/.env`) with `SUPABASE_URL` and `SUPABASE_KEY`
- [ ] **A `devices` row exists** whose `id` matches `DEVICE_ID` (else POST returns 404)
- [ ] **Windows Firewall allows inbound port 3000** (run once, Admin PowerShell):
      ```powershell
      New-NetFirewallRule -DisplayName "Plant Doctor backend 3000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3000
      ```
- [ ] **Arduino and PC on the same WiFi**, and the network has **no AP/client isolation**
      (campus/office/guest WiFi often block device-to-device; use a phone hotspot if so)

---

## Test steps

1. **Start the backend**
   ```powershell
   cd web/backend
   npm run server
   ```
   Expect: `Server running on http://localhost:3000`

2. **Smoke-test from the PC first** (isolates server bugs from network bugs).
   Replace `<real-uuid>` with the real `DEVICE_ID`:
   ```powershell
   curl.exe -X POST http://localhost:3000/api/sensor-data -H "Content-Type: application/json" -d "{\"device_id\":\"<real-uuid>\",\"moisture\":500,\"light\":300,\"temperature\":22,\"humidity\":40,\"roll\":1,\"pitch\":2,\"plant_status\":\"OK\"}"
   ```
   Expect: `201 {"message":"Sensor data saved"}`
   - If this works but the Arduino doesn't → the problem is **network/firewall**, not code.

3. **Upload the sketch**: open `arduino/plant_doctor_pro/plant_doctor_pro.ino` in the
   Arduino IDE → Upload → open **Serial Monitor @ 115200**.

4. **Watch the Serial Monitor** for:
   - WiFi connect + the Arduino's own IP
   - the printed JSON body
   - `HTTP Status Code: 201` → `Data sent successfully.`

5. **Confirm the row landed**: check Supabase `plant_data`, or the dashboard
   (set `VITE_USE_MOCK=false` in `web/frontend/.env` and restart `npm run dev`).

---

## Status code cheatsheet (from Serial Monitor)

| What you see        | Meaning                          | Fix |
|---------------------|----------------------------------|-----|
| Timeout / no status | Can't reach the server           | Firewall, wrong `SERVER_IP`, or AP isolation |
| `400`               | `device_id is required`          | JSON body / `DEVICE_ID` empty |
| `404`               | `Device not found`               | `DEVICE_ID` not in `devices` table |
| `500`               | Supabase / DB error              | Check backend `.env` + server console |
| `201`               | Saved ✅                          | — |
